# UI/UX Review: 2026-11-22

**Status:** Review complete; implementation not started.
**Baseline:** `e14724b` on `master`.
**Branch:** `plan/ux-review-2026-11-22`.
**Scope:** The running app in all three modes, the UI code, `DESIGN.md`, the dogfood findings, and Daniel's three target screens.
**Role:** Primary plan. The [security and integrity review](./review-2026-11-22.md) is the secondary plan.

## Summary

The app works end to end, but it does not yet feel like editing a document.
In Edit at 1440x900, the player fills the stage and the transcript shows one line. At 1024x700 it shows none.
Each word is a separate tab stop, arrow keys do nothing, and a delete drops keyboard focus.
Playback plays the words that the user deleted.
The core flow sends the user from Ingest to Edit, back to Ingest to transcribe, and back to Edit: 8 clicks and a typed name.
Deliver shows a list of scene ids, and a failed export prints a Node stack trace into the inspector.

The fix order: measure first, then the shell and the transcript, then the inspector.
The timeline and the export panel follow the integrity tracks that they need.

## Method

- Built the app and ran it on 127.0.0.1 through the shared heavy runner, with one capture script outside the repo.
- Reused the walkthrough fixtures: a fake ASR on localhost (3.5 s delay), a temporary HOME, and a generated 26 s H.264 take.
- Drove the real flow with `playwright-core` and system Chrome: create, import, transcribe, select, delete, reorder, silence, play, search, Deliver, export, error, and reload.
- Captured 52 screens at 1440x900 and 1280x800, and key screens at 1024x700. I read each screen.
- Measured clicks, tab stops, focus after delete, playback over deleted words, Space, Shift+Arrow, page scroll, and reload.
- Checked contrast for the `DESIGN.md` pairs and the code against the Web Interface Guidelines (fetched `command.md`).
- No paid API. No network beyond localhost.

Screens in this review: `measure/tracks/review_planning_20261122/screens/ux-*.png`.
Daniel's targets: `target-ingest.jpg`, `target-edit.jpg`, `target-deliver.jpg` in the same folder.
All other captures, `results.json`, and two ARIA snapshots stay in `/tmp/opencode/verbal-ux/shots/`.

## Findings

### U01 — High: The transcript is buried under the player

**Screens:** `ux-10-edit-transcript-1440.png`, `ux-10-edit-transcript-1024.png`.
**Code:** `apps/web/pages/index.tsx:1080-1100`; `apps/web/components/PlaybackScreen.tsx:252-346`.

The player, a 100px waveform strip, the scrubber, and the transport take the full stage height.
The transcript starts at y≈760 at 1440x900. At 1024x700 no word is in view.
`DESIGN.md` principle 4 says words are prominent. The user must scroll the stage to edit, and then loses the player.

**Fix direction:** Fix the stage as player (at most 40%), timeline, and a transcript that takes the rest and scrolls alone. Add Collapse Player.
**Track:** `ux_shell_flow_20261122` FR7.

### U02 — High: The core flow bounces between modes

**Screens:** `ux-06-ingest-path-filled-1440.png`, `ux-08-ingest-transcribing-1440.png`; capture `07-edit-no-transcript-1440.png`.
**Code:** `apps/web/pages/index.tsx:366-377`, `1093-1098`, `1493-1533`.

Import lands in Edit. Edit says "Transcribe it in Ingest". Transcribe sits in the Ingest inspector. Then the user goes back to Edit.
After a file is chosen in the picker, a second click (Import Copy) is still needed.
New project to editable transcript costs 8 clicks and a typed name.

**Fix direction:** Put import and transcription on one Ingest surface. Import on choose. Offer Transcribe in place in Edit. Target 5 clicks or less.
**Track:** `ux_shell_flow_20261122` FR3–FR5.

### U03 — High: The transcript has no keyboard model

**Screen:** `ux-18-focus-transcript-1440.png`.
**Code:** `apps/web/components/TranscriptEditor.tsx:77-131`.

Each word is a `<button>`, so the transcript is one tab stop per word. Arrow keys do nothing.
Shift+Arrow cannot select. Only Shift-click makes a range. Drag does not select. Space does not play.
This is the opposite of a word processor, and it makes keyboard editing of a long take impossible.

**Fix direction:** One focusable textbox with a caret word, `aria-activedescendant`, arrow and Shift+arrow selection, drag selection, and Space for play.
**Track:** `ux_transcript_document_20261122` FR1–FR3.

### U04 — High: Delete drops focus, and removed words are locked

**Screen:** `ux-12-edit-deleted-1280.png`.
**Code:** `apps/web/components/TranscriptEditor.tsx:122`; `apps/web/pages/index.tsx:593-600`.

A removed word is a disabled button. The focused word becomes disabled on delete, so focus falls to `body`.
The next key press goes nowhere. A removed word cannot be focused, selected, or restored. Only Undo brings it back, in order.

**Fix direction:** Keep the caret after a delete. Keep removed words in caret movement. Delete on a removed selection restores it.
**Track:** `ux_transcript_document_20261122` FR1, FR3.

### U05 — High: Playback plays the deleted words

**Screen:** capture `15-edit-playing-1440.png`; measure in `results.json` (`playThroughDeleted`).
**Code:** `apps/web/components/PlaybackScreen.tsx:196-226`.

The player plays the source. From 1.2 s, the highlight moves onto "show", "you", and "um", which are struck through.
The user cannot hear the edit before export. This breaks the product promise: the video follows the text.
This finding depends on F01 and F02 in the secondary review: there is no compiled edited timeline yet.

**Fix direction:** Play from one compiled timeline: skip cuts, follow order, play silence. Keep a Source toggle.
**Track:** `ux_timeline_playback_20261122`, after `edit_timeline_integrity_20261122`.

### U06 — High: Job status leaks across modes and errors stay silent

**Screens:** `ux-20-deliver-preview-1440.png`, `ux-23-export-error-1440.png`.
**Code:** `apps/web/pages/index.tsx:818-841`, `1687-1693`, `1718-1733`.

The export panel shows the last job of any kind. After transcription, Deliver reads "Job done · 100% · saving transcript" under Export.
`exportStoryboard` does not throw on a failed job, so the status bar keeps "Created 1 scene from the transcript" after a failure.

**Fix direction:** Scope job display by kind and project. Treat a failed job as an error in the pane and the status bar.
**Track:** `ux_deliver_export_20261122` FR3.

### U07 — High: A failed export prints a stack trace

**Screen:** `ux-23-export-error-1440.png`.
**Code:** `apps/web/pages/index.tsx:1687-1693`.

The inspector prints the full Node `ERR_MODULE_NOT_FOUND` trace. The text runs past the right edge and is clipped.
There is no plain message, no next step, and no Retry. The cause here is environmental: the Remotion tool is not installed (F16).
A clean install cannot finish an export, and the UI does not say why in plain words.

**Fix direction:** Map known failures to a plain message with a next step; keep raw text in a details line; wrap; add Retry.
**Track:** `ux_deliver_export_20261122` FR3, with the copy map in `ux_gates_20261122` FR4. F16 stays in `repository_contracts_20261122`.

### U08 — Medium: Edit tools sit far from the selection

**Screen:** `ux-18-focus-transcript-1440.png`.
**Code:** `apps/web/pages/index.tsx:1165-1242`.

Silence, Split, Move Back, Move Forward, Delete, Undo, Redo, and Save sit in a footer row under the transcript.
At 1280x800 during playback the row is below the visible stage. The labels "Move back/forward" differ from the reorder track ("Move earlier/later").
A Save button sits beside autosave and suggests that work is not saved.

**Fix direction:** A floating selection toolbar (as in `target-edit.jpg`); Undo and Redo move to the inspector history; remove Save; keep Ctrl+S.
**Track:** `ux_transcript_document_20261122` FR4.

### U09 — Medium: Text contrast fails AA

**Screens:** `ux-12-edit-deleted-1280.png`, `ux-10-edit-transcript-1440.png`.
**Code:** `apps/web/styles/globals.css:412-415`, `426-430`.

Removed words: #707070 on #252525 is 3.10:1. White on the indigo active word is 4.47:1. Error red on surface is 4.43:1.
Removed words are content: the user reads them to decide what to restore.

**Fix direction:** Raise the removed-word color, use `primary-focus` behind white text, and record each token change in `DESIGN.md`.
**Track:** `ux_gates_20261122` FR2.

### U10 — Medium: Focus and selection look the same

**Screen:** `ux-18-focus-transcript-1440.png` ("want" has focus, "the" is selected).
**Code:** `apps/web/styles/globals.css:378-381`, `417-419`.

Both show as an indigo outline. The user cannot tell where the keyboard is from what will be deleted.
`DESIGN.md` asks for an indigo tint background on the selection.

**Fix direction:** Selection gets the tint and a thin border; the caret gets a 2px bar; the focus ring stays on the textbox.
**Track:** `ux_transcript_document_20261122` FR5.

### U11 — Medium: Disabled primary buttons look enabled

**Screens:** `ux-06-ingest-path-filled-1440.png` (Transcribe Media, Stop Preview), `ux-10-edit-transcript-1440.png` (Remove Accepted).
**Code:** `apps/web/components/CapturePanel.tsx:40-71`; disabled styles in `apps/web/styles/globals.css`.

A disabled primary button keeps a dim indigo fill. It reads as an action that does nothing on click.
Capture buttons do not use the shared button classes, so all four look primary.

**Fix direction:** A neutral disabled style; shared classes on Capture.
**Track:** `ux_gates_20261122` FR3.

### U12 — Low: Off-scale type, a gradient, and two live regions

**Code:** `apps/web/styles/globals.css:678`, `1004`, `1154`, `1216`; `apps/web/pages/index.tsx:964`, `1535`, `1727-1730`.

Three 10px sizes sit outside the `DESIGN.md` scale. The brand mark uses a gradient, which `DESIGN.md` forbids.
The save state, the transcription line, and the status bar are three `role="status"` regions. Buttons mix sentence case and Title Case.

**Fix direction:** Scale sizes, a flat mark, one polite live region, Title Case.
**Track:** `ux_gates_20261122` FR3–FR5.

### U13 — Medium: A reload forgets the project, and nothing warns

**Screen:** `ux-25-after-reload-1440.png`.
**Code:** `apps/web/pages/index.tsx:286-298`.

The page remembers the browsed folder only. A reload in Edit lands in Ingest with "No project open".
A reload with unsaved edits gives no `beforeunload` warning.

**Fix direction:** Persist the project root and mode; reopen on load; warn while edits are unsaved or a job runs.
**Track:** `ux_shell_flow_20261122` FR6.

### U14 — Medium: The browser hides outside Ingest and goes stale

**Screens:** `ux-08-ingest-transcribing-1440.png`, `ux-10-edit-transcript-1440.png`.

The browser shows only in Ingest. The open project row has no marker.

### U15 — Medium: Ingest leads with the camera, not the take

### U16 — Medium: Cleanup review is jargon and not tied to the text

**Screen:** `ux-10-edit-transcript-1440.png`.

Rows show "Cover: punch-in" and "95%". Checkbox names are ids ("Accept proposal p3").

**Fix direction:** Category cards with counts; a review list that selects and seeks; names made of words and time; no save hint; freeze under Advanced with one line of help.

### U17 — Medium: The inspector says nothing about the edit

**Track:** `ux_gates_20261122` FR6.

## What already works

- The shell holds: no page scroll in any mode at 1440, 1280, or 1024.
- Empty states name the next action (No project open, No scenes yet → Create Storyboard).
- The picker opens where the browser was and lists only media files.
- Autosave reaches "Saved" about 2.5 s after an edit with no click.
- Search marks matches and steps between them.

## UX improvement plan

The tracks run in this order. Each has a spec with testable acceptance criteria and a test-first plan.

1. **UX Gates and Design Conformance** — `ux_gates_20261122`.
   Build the gate that counts clicks, tab stops, lines in view, names, and contrast. Fix tokens, type, and copy.
2. **Shell and Core Flow** — `ux_shell_flow_20261122`.
   Browser in all modes; transcript-first Edit stage; import and transcription in one place; inline errors; session memory.
3. **Transcript as a Document** — `ux_transcript_document_20261122`.
   One focus target with a caret; keyboard and drag selection; restore; floating toolbar; follow-scroll.
4. **Edit Inspector and Cleanup Review** — `ux_edit_inspector_20261122`.
   Selection times, cut summary, a cleanup review tied to the text, and undo history.
5. **Edited Timeline and Playback** — `ux_timeline_playback_20261122`.
   Kept and cut overlay and edit playback. Needs `edit_timeline_integrity_20261122` first.
6. **Deliver Strip and Export Panel** — `ux_deliver_export_20261122`.
   Scene strip and an export panel with honest states and Cancel. Needs `save_export_integrity_20261122` and `job_lifecycle_20261122` first.

## Limits of this review

- Export could not finish on this machine: the brand render needs `@remotion/bundler`, which a clean install omits (F16). The done state is from code, not a screen.
- The transcript came from a fake ASR. Real ASR output can have different segment sizes.
- The camera path was not exercised; headless Chrome has no camera stream.
- No screen reader test was run. The tracks add one Orca check.
- The target screens are images, not specs. Their text has typos.

## Verification

- Capture: one heavy-runner call ran `npm run build`, started the standalone server on 127.0.0.1, ran `/tmp/opencode/verbal-ux/capture.mjs`, and stopped the server. Build OK; capture finished with no script failure.
- Browser console: four 404 responses for `/api/transcript` and `/api/cleanup` on projects with no transcript. The walkthrough treats these as expected.
- Formatting and `npm run check` results are in the review planning plan, Phase 2.
